# Stealth Puyo

Windows / PyQt5 단일 파일 낙하 퍼즐. **숨기기**를 중심으로 만든 앱입니다.
**뿌요뿌요 · 테트리스 · 스도쿠 · 지뢰찾기** 네 가지가 들어 있고, 창을 꺼내지 않고
**트레이 아이콘 우클릭**만으로도 바로 갈아끼울 수 있습니다.

같은 저자의 `txt viewer`(Stealth TXT Reader)에서 은폐 구조 — 전역 핫키 숨김,
배경 지우기, 위장 창, 트레이 상주 — 를 그대로 이어받고, 게임 부분은 본가
규칙으로 새로 만들었습니다.

```bash
pip install PyQt5
```

```bash
python stealth_puyo.py
```

## 1. 숨기기 (핵심)

| 상황 | 방법 |
|---|---|
| 즉시 숨기기 | `Esc` — 창이 사라지고 판은 그대로 얼어붙는다 |
| 어디서든 숨기기 / 복귀 | `Ctrl+Alt+Z` — 다른 프로그램을 쓰는 중에도 동작하는 전역 핫키 |
| 배경 지우기 | `Ctrl+B` / `Ctrl+Alt+B` — 창 배경이 완전히 사라지고 뿌요만 화면에 뜬다 |
| 빠른 재시작 | `R` 또는 `F2`, 어디서든 `Ctrl+Alt+F2` — 확인 없이 즉시 새 판 |
| 다른 창을 보면서 플레이 | `Ctrl+Alt+←→↓↑`, `Ctrl+Alt+Enter` 전역 조작키 |
| 창 자체를 감추기 | 설정 → 창 모드 `숨은 창` — 작업 표시줄·Alt+Tab 목록에서 빠진다 |
| 다른 이름으로 위장 | 설정 → 창 모드 `위장 창` + 위장 제목(기본 "메모장") |
| 포커스를 잃으면 자동 숨김 | 설정 → 화면 → "포커스를 잃으면 자동으로 숨기기" |
| 트레이에서 꺼내기 | 트레이 아이콘 클릭 (툴팁에 등록된 전역 키 목록이 나온다) |
| 창 없이 게임 바꾸기 | 트레이 아이콘 우클릭 → 게임. 숨어 있는 채로 바꾸면 새 판은 얼려 둔다 |
| 종료 | `Ctrl+Alt+Q` 또는 트레이 → 종료. 창 닫기(`X`)는 종료가 아니라 숨기기 |

동작 방식

- **전역 핫키** — `RegisterHotKey` 로 OS에 직접 등록하고 `WM_HOTKEY` 를
  네이티브 이벤트 필터에서 받는다. 창이 포커스를 갖고 있지 않아도 동작한다.
  수식키(Ctrl/Alt/Shift/Win) 없는 조합은 위험해서 등록을 거부한다.
- **배경 지우기** — 테두리 없는 창에 `WA_TranslucentBackground` 를 켜고
  배경을 직접 칠한다. 배경 알파를 `0` 으로 내리면 아무것도 칠하지 않아
  뒤쪽 창의 글자가 그대로 보이고 뿌요만 공중에 뜬다.
- **숨길 때 자동 일시정지**(기본 켜짐) — 숨긴 사이에 판이 진행되어 게임
  오버가 되는 일이 없다. 복귀하면 `P` 로 재개. 숨어 있는 동안
  `Ctrl+Alt+F2` 로 재시작해도 판은 얼린 채로 둔다.
- **전역 키가 이미 쓰이고 있으면** 등록에 실패한다. 어떤 키가 실패했는지
  트레이 툴팁과 상단바에 알려 주니, 설정 → 단축키에서 다른 조합으로 바꾸면 된다.
  (예: `Ctrl+Alt+R` 은 다른 프로그램이 자주 선점해서 기본값에서 뺐다.)

## 2. 게임 규칙 (최신 뿌요뿌요 계열)

- **필드** 6열 × 12줄 + 숨은 13번째 줄. 숨은 줄의 뿌요는 터지지 않는다.
- **게임 오버** 3열(가운데 왼쪽) 숨은 줄이 막히면 종료 — 본가와 같은 판정.
- **조** 축뿌요 + 자뿌요. 자뿌요가 축뿌요를 돌며 회전한다.
- **회전 보정** 벽 밀기(벽에서 돌리면 축이 밀린다), 바닥 밀기(바닥에서
  아래로 돌리면 축이 한 칸 뜬다), **퀵턴**(좌우가 모두 막히면 180도 뒤집기).
- **굳기 지연** 바닥에 닿아도 0.42초 여유가 있고, 이동·회전하면 초기화된다.
- **중력** 굳힌 직후 · 터진 직후 · 방해뿌요가 쏟아진 직후에는 떠 있는 뿌요가
  가속을 받으며 실제로 떨어지고(`drop` 단계), **낙하가 완전히 끝난 뒤에만**
  다음 터짐을 판정한다. 그래서 연쇄가 한 단계씩 눈에 보인다.
- **점수** 본가 공식 `10 × 지운 개수 × (연쇄 + 색 + 덩어리 보너스)`
  - 연쇄 보너스 0, 8, 16, 32, 64, 96, … (19연쇄 이후 32씩)
  - 색 보너스 1색 0 / 2색 3 / 3색 6 / 4색 12
  - 덩어리 보너스 4개 0 … 10개 7 / 11개 이상 10
- **싹쓸이(전체 지우기)** 판을 비우면 그 자리에서 점수가 들어오지 않는다.
  본가처럼 **다음 공격에 얹힌다** — 비운 턴에는 "싹쓸이 대기"만 표시되고,
  그 뒤 처음으로 연쇄를 터뜨리는 턴에 점수 +2100 과 방해뿌요 30개가 함께
  나간다. 공격을 못 하는 턴이 몇 번 이어져도 보너스는 사라지지 않고 기다린다.
- **방해뿌요** 색 덩어리를 만들지 않고, 옆에서 뿌요가 터지면 함께 사라진다.
  천장에서 한꺼번에 쏟아지며 한 번에 최대 30개(5줄)까지 떨어진다.
- **상쇄** 번 점수를 목표 점수(기본 70)로 나눈 수만큼 예고 방해뿌요를 지우고,
  남으면 밖으로 보낸다(전송 표시).
- **마진 타임** 96초 이후 16초마다 목표 점수가 내려가 방해뿌요가 무거워진다.
- **NEXT 2조**, 착지 위치 표시, 연쇄 수 표시.
- **색** 빨강 · 파랑 · 노랑 · 초록 네 가지. 본가 뿌요테트의 기본 대전 색 수도
  4색이다. 설정에서 3색으로 줄일 수 있다.
- **뿌요 생성** 본가와 같은 방식이다.
  - 판이 시작될 때 쓸 색을 골라 **한 판 동안 고정**한다.
  - 길이 **256조의 순서표**를 미리 뽑아 두고, 끝까지 쓰면 처음으로 돌아간다.
  - 각 뿌요는 **독립 균등 추첨**이다. 어느 색도 더 자주 나오지 않고, 같은 색
    조(더블)는 1/색수 확률로 나온다(4색이면 25%).
  - **처음 세 조는 3색만** 쓴다(첫 수부터 막히지 않게). 어떤 색을 뺄지도
    무작위로 정하고, 네 번째 조부터 전체 색이 나온다.
  - 색 수 설정을 판 도중에 바꿔도 진행 중인 판의 색 세트는 그대로다 — 바꿔
    버리면 판에 남은 색이 다시 나오지 않아 영구히 지울 수 없는 뿌요가 생기기
    때문이다. (아직 아무것도 놓지 않은 판이면 즉시 새 색으로 다시 깐다.)
- **속도** 15조마다 레벨이 올라 낙하가 빨라진다(최대 20레벨).

### 모드

- **엔드리스** — 혼자 연쇄를 쌓는 연습판.
- **방해뿌요** — 레벨에 따라 일정 간격으로 방해뿌요가 쏟아진다. 연쇄로 상쇄한다.

## 2-2. 테트리스 규칙 (본가 뿌요테트 / 가이드라인)

- **필드** 10×20. 조각은 그 위 숨은 줄에서 가운데로 나온다.
- **SRS 회전** 회전 상태와 벽 밀기 표를 그대로 따른다. I 는 따로 된 표를 쓰고,
  O 는 돌아도 움직이지 않는다. 180도 회전도 있다.
- **7-bag** 일곱 조각을 섞어 한 묶음씩 내보낸다 — 같은 조각이 연달아 몰리지 않는다.
- **홀드** 조각마다 한 번. 이미 쓴 홀드는 흐리게 보인다.
- **굳기 지연** 바닥에 닿아도 0.5초 여유가 있고, 이동·회전으로 15번까지 미룰 수
  있다. 여태보다 더 낮은 줄로 내려가면 지연과 미루기 횟수가 모두 처음으로
  돌아간다. **소프트 드롭(↓)은 굳히지 않는다** — 바닥에 닿은 뒤에도 자리를 잡을
  수 있고, 즉시 굳는 것은 하드 드롭뿐이다.
- **T-스핀** 3코너 판정. 앞 두 모서리가 비면 미니로 친다(마지막 벽 밀기로 들어간
  경우는 정식으로 친다). 회전으로 끼워 넣었을 때만 인정한다.
- **점수** 가이드라인 값에 레벨을 곱한다.
  - 싱글 100 / 더블 300 / 트리플 500 / 테트리스 800
  - T-스핀 400, 싱글 800, 더블 1200, 트리플 1600 (미니 100 / 200)
  - 백투백(테트리스·T-스핀이 이어지면) ×1.5, 콤보 50 × 콤보수
  - 퍼펙트 클리어 800~2000, 소프트 드롭 1점/칸, 하드 드롭 2점/칸
- **보내는 줄** 뿌요테트 공격표 — 더블 1, 트리플 2, 테트리스 4, TSS 2, TSD 4,
  TST 6, 백투백 +1, 콤보 보너스, 퍼펙트 클리어 +10.
- **중력** 가이드라인 곡선 `(0.8 - (Lv-1)×0.007)^(Lv-1)` 초/칸. 10줄마다 레벨이 오른다.
- **NEXT 5개**, 착지 위치 표시.

본가와 다른 점 하나 — 180도 회전의 벽 밀기는 공개된 표가 없어서, 제자리에서
안 되면 위아래·좌우로 한 칸씩만 밀어 본다.

### 모드 (테트리스)

- **엔드리스** — 혼자 쌓는 연습판.
- **방해줄** — 일정 간격으로 구멍 하나 뚫린 줄이 아래에서 올라온다. 지우기로 상쇄한다.

## 2-3. 스도쿠 규칙 (sudoku.com 기준)

- **난이도 여섯 단계** — 쉬움 / 보통 / 어려움 / 전문가 / 마스터 / 익스트림.
- **실수 몇 번이면 끝인지 고른다** — 1 / 3 / 5 / 제한 없음 (기본 3, sudoku.com 과
  같다). 틀린 숫자는 빨갛게 남겨 두고 실수로 센다. 제한 없음으로 두어도 틀린 칸이
  사라지지는 않는다 — 끝나지 않을 뿐이다. 이 값은 **지금 풀던 판에도 바로 적용된다.**
- **이어하기** 풀던 판은 앱을 껐다 켜도 그대로 나온다. 숫자·메모·틀린 칸·실수·힌트
  횟수와 **흘러간 시간까지** 이어진다. 진행 중에는 10초마다, 숨길 때와 끝낼 때
  담아 둔다. `F2` / `R` 로 새 문제를 뽑으면 담아 둔 판은 버린다.
- **메모(연필) 모드** — 숫자판 위의 **켜고 끄는 스위치**로 바꾼다(`N` 키도 된다).
  켜고 숫자를 누르면 작은 후보 숫자가 켜지고 꺼진다. 숫자를 확정하면 같은
  줄·칸·박스의 그 숫자 메모가 자동으로 지워진다. 켜 두면 화면이 이렇게 달라진다.

  | | 평소 | 메모 켜짐 |
  |---|---|---|
  | 고른 칸 | 파란 바탕 | **노란 바탕 + 점선 테두리** |
  | 같은 숫자 강조 | 파랑 | 노랑 |
  | 숫자판 1~9 | 칸 가운데 큰 숫자 | **그 숫자가 메모로 적힐 자리에 작게** — 누르기 전에 어디 찍힐지 보인다 |
  | 스위치 | 손잡이 왼쪽, 회색 | 손잡이 오른쪽, 노랑 |
  | 상단바 | 시간 · 실수 | `✎ 메모` 가 앞에 붙는다 |

  색만 바꾸면 색약인 눈에 안 걸릴 수 있어 점선·손잡이 위치·글자까지 함께 바꿨다.
  옆 칸을 꺼 두고 쓰는 경우를 위해 상단바에도 표시를 남긴다.
- **힌트** 고른 칸에 정답을 넣는다. 실수로 세지 않고 힌트 수만 올라간다.
- **되돌리기** 넣기·지우기·메모를 한 단계씩 물린다.
- **밝기 표시** 고른 칸의 줄·칸·박스, 그리고 판 전체에서 같은 숫자를 함께 밝게.
- **숫자판** 1~9 아래에 그 숫자를 앞으로 몇 개 더 놓아야 하는지 보여 준다.
- **타이머** 시작부터 지금까지. 다 풀면 그 자리에서 멈춰 **걸린 시간**이 되고,
  완성 화면과 옆 칸에 그대로 남는다. 난이도별 최고 기록(가장 짧은 시간)을
  갱신했으면 완성 화면이 그렇게 알려 준다.
- **글자 색** sudoku.com 처럼 처음부터 있던 숫자(흐린 흰색)와 내가 넣은
  숫자(굵은 파랑)를 색으로 가른다. 틀린 숫자는 빨강, 메모는 회색이다.
  배경을 옅게 두면 뒤쪽 창이 비쳐 글자가 묻히므로, 투명도가 높을 때는
  숫자 뒤에 어두운 그림자를 한 겹 깔아 밝은 문서 위에서도 읽히게 했다.

### 난이도를 가르는 기준

문제는 완성된 판에서 숫자를 하나씩 걷어내 만든다. 걷어낼 때마다 **해가 하나뿐
인지 확인**하므로 모든 문제는 유일해가 보장된다. 그 뒤 **사람이 쓰는 기법만으로
실제로 풀어 보고** 등급을 매긴다. 추측으로 훑어서 푸는 일은 없다.

풀이기가 쓰는 기법 (쉬운 것부터)

| 단계 | 기법 |
|---|---|
| 0 | 단일값 (naked / hidden single) |
| 1 | 후보 가두기 (pointing / claiming) |
| 2 | 드러난·숨은 쌍·삼중·사중 |
| 3 | X-Wing · Swordfish · Jellyfish |
| 4 | XY-Wing · XYZ-Wing · 색칠(단순 컬러링) · 유니크 렉탱글 |
| 5 | 포싱 체인 — 후보 하나를 가정해 끝까지 밀어 보고, 모순이 나오면 그 후보를 지운다(가설 검증). 두 갈래가 같은 결론을 내면 그 값을 확정한다 |
| 6 | 깊은 포싱 체인 — 후보가 셋인 칸까지 가정하고, 가정 안에서도 후보 가두기를 써 가며 더 멀리 민다 |

| 난이도 | 주어진 숫자 | 필요한 단계 |
|---|---|---|
| 쉬움 | 40~45칸 | 0 |
| 보통 | 34~38칸 | 0 |
| 어려움 | 30~33칸 | 0~2 |
| 전문가 | 27~30칸 | 1~4 |
| 마스터 | 25~28칸 | 3~4 |
| 익스트림 | 22~26칸 | **5~6 (포싱 체인이 반드시 필요하고, 그것으로 반드시 풀린다)** |

위 기법으로도 안 풀리는 문제(7단계)는 **어느 난이도에서도 내보내지 않는다.**
사람이 찍어야 하는 문제를 주지 않기 위해서다.

난이도별로 12판씩 만들어 규격을 확인했고 여섯 단계 모두 12/12 였다. 문제 만드는
데 쉬움은 10ms 안쪽, 마스터·익스트림은 평균 0.6초(최대 1.9초)쯤 걸린다.

**익스트림 위에 한 단계를 더 두지 않은 이유.** 주어진 숫자를 21~25칸까지 줄여
"악몽" 단계를 만들어 봤지만, 칸을 더 걷어낼수록 판이 성기어져 오히려 단일값으로
술술 풀리는 문제가 늘었다(34판 중 26판이 포싱 체인 없이 풀림). 걷어낸 칸 수는
난이도와 비례하지 않는다. 익스트림이 이 방식으로 만들 수 있는 실질적인 천장이라
판단해 넣지 않았다.

#### 검증
독립으로 다시 짠 풀이기로 교차 확인했다. 그 풀이기는 후보를 지울 때마다 "정답
후보를 지우지는 않았는지" 스스로 검사한다 — 25판에서 잘못 지운 경우 0건이었으니
측정값 자체를 믿을 수 있다. 이 과정에서 **숨은 부분집합(hidden subset)이 이미
그 줄에 놓인 숫자를 후보로 끼워 넣어 엉뚱한 칸을 지우던 버그**를 찾아 고쳤다.
고치기 전에는 익스트림의 1/3이 실제로는 쉬운 문제였다.

점수는 sudoku.com 이 식을 공개하지 않아 그대로 옮길 수 없었다. 난이도별 기본
점수에서 걸린 시간·실수·힌트만큼 깎는 방식으로 비슷하게 맞춰 두었다.

문제를 만드는 데 쉬움은 10ms 안쪽, 익스트림은 평균 0.5초(최대 1.5초)쯤 걸린다.

## 2-4. 지뢰찾기 규칙 (원작 그대로)

원작(윈도우 지뢰찾기)의 규칙과 조작을 그대로 옮겼다.

| 난이도 | 판 | 지뢰 |
|---|---|---|
| 초급 | 9 x 9 | 10 |
| 중급 | 16 x 16 | 40 |
| 고급 | 30 x 16 | 99 |

- **왼쪽 클릭** 칸 열기. **오른쪽 클릭** 깃발 → 물음표 → 해제.
  물음표는 설정에서 끌 수 있다(원작에도 있는 옵션). 깃발이 꽂힌 칸은 열리지
  않지만 **물음표는 막아 주지 않는다** — 원작과 같다.
- **양쪽 버튼**(또는 가운데 버튼) 숫자 칸에서 누르면 주변이 한꺼번에 열린다.
  꽂아 둔 깃발 수가 그 숫자와 같을 때만 열리고, **깃발이 틀렸으면 그대로
  터진다.** 원작도 봐주지 않는다.
- **0 이면 주변이 줄줄이 열린다.** 깃발이 꽂힌 칸은 건너뛴다.
- **첫 칸은 절대 지뢰가 아니다.** 원작(winmine)의 방식 그대로 — 지뢰를 미리
  깔아 두고, 첫 칸이 지뢰면 왼쪽 위부터 훑어 첫 빈 칸으로 **옮긴다**. 첫 칸이
  반드시 0 이 되도록 주변까지 비워 주는 요즘 방식과는 다르다.
- **남은 지뢰 수 = 지뢰 − 깃발.** 깃발을 많이 꽂으면 원작처럼 음수가 된다.
- **다 열면** 남은 지뢰에 깃발이 자동으로 꽂히고 시계가 멈춘다.
- **밟으면** 밟은 칸이 빨갛게, 나머지 지뢰가 모두 드러나고 **잘못 꽂은 깃발에는
  X** 가 그려진다.
- **시계는 첫 칸을 열 때부터** 돈다 (원작처럼 999 에서 멈춰 보인다).
- 난이도별 최고 기록은 원작과 같이 **시간**이다.

원작과 다르게 둔 것은 색뿐이다. 숫자 색은 원작 그대로지만(1 파랑, 2 초록,
3 빨강 …), 4(남색)와 7(검정)은 이 앱의 어두운 판에서 안 보여 같은 계열의 밝은
쪽으로 올렸다. 지뢰도 원작은 밝은 회색 판 위의 검은 공인데, 여기서는 판이
어두우니 밝고 어두운 쪽을 맞바꿨다.

## 3-1. 배경이 옅을 때의 가시성

`배경 진하기` 를 낮추거나 `배경 지우기` 를 켜면 뒤 창이 그대로 비친다. 이때
**흰 문서 위에 올리면 흰 격자선과 흰 테두리가 통째로 사라져서**, 판이 어디서
시작하고 끝나는지조차 안 보였다. 색을 바꿔서는 못 고친다 — 어두운 바탕에서 잘
보이는 색과 밝은 바탕에서 잘 보이는 색이 서로 반대다.

그래서 **밝은 것 뒤에 어두운 것을 한 겹 깐다.** 어느 바탕에서도 둘 중 하나는
남는다. 배경이 옅을수록 세게 주고, 배경을 살려 둔 사람에게는 아무것도
달라지지 않는다 (`faint_strength()` 가 0~1 로 정도를 돌려준다).

**부담스러우면 통째로 끈다** — 설정 → 화면 → `배경이 옅을 때 또렷하게`.
끄면 보조선도 받침도 없이 예전처럼 그린다. 아래의 모든 보조가
`faint_strength()` 하나를 거치므로, 거기서 0 을 돌려주면 그리는 길이 전부
예전으로 돌아간다. 세 게임 x 배경 진하기 4단계, 열두 가지 조합을 판과 창
양쪽에서 렌더해 **픽셀 하나까지 예전 버전과 같은 것을 확인**했다.

| 대상 | 한 일 |
|---|---|
| 격자선 | 밝은 선을 긋기 전에 어두운 선을 1px 어긋나게 먼저 긋는다 |
| 판 테두리 | 어두운 굵은 선 + 밝은 얇은 선을 겹쳐 두른다 (네 게임 모두) |
| 판 위 숫자 | 글자 뒤에 어두운 그림자 (스도쿠) |
| 옆 칸·상단바 글 | 글자 뒤에 어두운 받침을 깐다 |

옆 칸·상단바만 그림자가 아니라 받침인 이유 — 거의 흰 글자는 테두리를 아무리
진하게 둘러도 획 안쪽이 흰 바탕과 같은 색이라 읽히지 않는다. 뒤에 받침을
깔아야 글자가 놓일 자리가 생긴다.

흰 문서 위, 배경 지우기 상태에서 잰 값 (WCAG 명암비)

| | 전 | 후 |
|---|---|---|
| 격자선 | 1.00 (아예 안 보임) | 5.49 |
| 옆 칸 글 | 1.18 | 5.95 |

## 3-2. 이어하기

`config.json` 의 `saves` 칸에 게임별로 한 판씩 담는다. 게임마다 켜고 끌 수
있도록 `GameSpec` 에 `dump` / `restore` 두 함수를 달아 두었고, 둘 다 있어야
`spec.resumable` 이 참이 된다. 지금은 **스도쿠만** 쓴다 — 뿌요·테트리스는
손이 쉬지 않는 게임이라 몇 초 끊겼다 이어 봐야 의미가 없다.

```
dump(game)          -> JSON 에 담을 수 있는 dict, 담을 게 없으면 None
restore(game, data) -> 되살렸으면 True
```

되살릴 때 지키는 것

- **꺼낼 때 지운다.** 되살리다 넘어져도 깨진 기록이 남지 않으니, 켤 때마다
  같은 자리에서 다시 넘어지는 일이 없다.
- **조금이라도 어긋나면 손대지 않고 물러난다.** 정답이 완성된 판인지, 주어진
  숫자가 정답과 맞는지까지 본다. 어디서 온 파일인지 모르는 값을 그대로 믿고
  판을 세우지 않기 위해서다. 물러나면 그냥 새 판으로 시작한다.
- **틀린 칸은 저장값을 믿지 않고 판에서 다시 센다.** 늘 판과 맞는다.
- **되돌리기 기록은 담지 않는다.** 이어 푸는 데 필요 없고, 앱을 껐다 켠 뒤의
  "한 수 전"이 무엇인지도 모호하다.

## 3-3. 표시 언어

설정 → 화면 → **언어** 에서 한국어 / English 를 고른다. 고르는 즉시 창·상단바
툴팁·트레이 메뉴·설정 창이 모두 새 언어로 다시 그려진다. 고른 값은
`settings.lang` 에 남아 다음에 켤 때도 그대로다.

옮긴 말은 `TR` 표 한 곳에 모여 있다. 표에 없는 말이 화면에 나오면 그대로
출력하되 `_TR_MISS` 에 적어 두므로, 빠뜨린 문구를 찾을 때는 세 게임을 모두
돌려 본 뒤 그 집합을 보면 된다. 지금은 네 게임 × (진행·종료·일시정지) + 메뉴 +
트레이 + 설정 세 탭 + 모든 동작 이름을 훑어 빠진 문구가 없다.

말을 화면에 낼 때 옮겨야지, 모듈이나 클래스를 만들 때 `tr()` 을 부르면 안 된다.
그 시점에는 아직 설정을 읽기 전이라 한국어로 굳어 버린다.

## 4. 설정 저장

`%APPDATA%\StealthPuyo\config.json` — 임시 파일에 쓰고 교체하므로 도중에 죽어도
깨지지 않는다. 게임이 여럿이어도 섞이지 않도록 이렇게 나눠 담는다.

```
settings   화면·은폐·창 위치·낙하 속도·언어  — 게임이 바뀌어도 그대로
games      { 게임 이름: 그 게임 전용 설정 }
records    { 게임 이름: { 기록 이름: 값 } }
game       지금 고른 게임
keys       단축키 (게임과 무관하게 하나로 관리)
saves      { 게임 이름: 풀다 만 판 }  — 이어하기 (3-2 참고)
```

예전 형식(모든 값이 한 덩어리였던 파일)은 처음 읽을 때 알아서 옮겨 담는다.
투명도·창 위치·단축키는 그대로 남고, 뿌요 설정과 최고 기록은 뿌요 칸으로 간다.

같은 앱을 두 번 실행하면 새 창이 아니라 이미 떠 있는 창이 나온다(단일 인스턴스).


`dist` 폴더에 `Notepad.exe` 가 만들어진다. 콘솔 창 없는 단일 파일이다.

빌드 설정은 `Notepad.spec` 에 있다. 이 앱이 쓰지 않는 Qt 모듈(소프트웨어
OpenGL 21MB, QML/Quick, OpenSSL)을 걷어내 40MB → 24MB 로 줄여 둔 것이니,
실행에 문제가 생기면 spec 의 `DROP_BINARIES` 를 빈 목록으로 두고 다시 빌드하면
원래대로 돌아온다.

```bash
python -m PyInstaller --noconfirm Notepad.spec
```

**반드시 spec 으로 빌드한다.** `stealth_puyo.py` 를 PyInstaller 에 직접 넘기면
PyInstaller 가 `Notepad.spec` 을 새로 만들어 덮어쓴다. 그러면 위 설정이 전부
사라져 결과물이 40MB 로 돌아가고 스펙의 주석과 목록도 날아간다. `build.bat` 도
spec 을 쓰도록 해 두었다.

실행 파일 이름은 spec 의 `name` 값으로 바꾼다.

빌드할 때 앱이 실행 중이면 `dist` 안의 exe 가 잠겨 실패한다. `Ctrl+Alt+Q` 로
종료한 뒤 다시 빌드한다.

### 게임 붙이기

새 게임은 `GameSpec` 하나를 만들어 `register_game()` 에 넘기면 된다. `PuyoWindow`
와 `Config` 는 고칠 일이 없다.

```python
register_game(GameSpec(
    key="...", label="...",
    defaults={...},            # 이 게임 전용 설정 (공용과 이름이 겹치면 거부된다)
    engine=...,                # reset / update(dt) / move / rotate /
                               # soft_drop / hard_drop, score·over·state
    board=..., side=...,       # 필드 위젯, NEXT 같은 옆 위젯(없으면 None)
    stats=..., settings_tab=...,
    actions={...},             # 이 게임이 쓰는 조작 id — 안 쓰는 키는 설정 창에서 숨는다
    records=...,               # {기록 이름: 값}
    wants_mouse=False,         # True 면 필드와 옆 위젯이 클릭을 받는다 (스도쿠)
))
```

키 표는 지금 고른 게임이 쓰는 동작으로만 만든다. 그래서 같은 키를 게임마다 다른
일에 쓸 수 있다 — `↓` 는 뿌요·테트리스에서 빠른 낙하지만 스도쿠에서는 칸 커서를
내린다. 기록은 큰 값으로만 갱신하므로, 스도쿠의 "가장 짧은 시간"처럼 작을수록
좋은 기록은 음수로 담아 둔다.

창이 게임 객체에 요구하는 이름은 서른 개 남짓이고, 창 크기·드래그·숨기기·투명도·
트레이·단축키는 전부 공용 계층이 처리한다. 게임이 둘 이상이면 설정 창의 게임 탭과
창 우클릭 메뉴, 트레이 아이콘 우클릭 메뉴에 게임 고르기가 나타나고,
`PuyoWindow.switch_game()` 이 규칙·필드·옆 위젯·조작표를 한꺼번에 갈아끼운다.
트레이 메뉴는 한 번만 만들어 두고 열릴 때마다 체크 표시를 다시 찍는다.

창 크기는 보드에서 곧바로 계산하고 패널 높이도 보드에 맞춰 못박는다. 레이아웃이
관리 위젯에 심어 둔 최소 크기가 남아 있으면, 판이 작은 게임으로 바꿔도 창이 옛
크기 아래로 줄지 않기 때문이다.

설정 창 색은 두 가지를 함께 해야 한다. 윈도우 기본 스타일은 스타일시트를 준
위젯과 그렇지 않은 위젯을 섞어 그려서 버튼 같은 일부만 시스템 흰색으로 남고,
글자색은 밝은 색이 적용되어 흰 바탕에 흰 글씨가 된다. 그래서 (1) 스타일을
Fusion 으로 고정하고, (2) 팔레트를 자손 위젯 하나하나에 직접 넣는다. 부모에게만
주고 상속에 맡기면 스크롤 영역 안쪽이나 `QKeySequenceEdit` 내부처럼 Qt 가 자기
팔레트를 따로 들고 있는 위젯이 흰색으로 남는다.
